# Security review — `main` at `8b600b3`, 11 October 2026

First run of the release security review (#348). Report only: nothing was fixed here. Fixes are
in the issues below. #349 (headers, body limit, cross-site check, timeouts) was written in the same
session, after this review; it is not covered by this review, so the next release's review must
look at it with a reviewer that did not write it.

## Who reviewed, and how

The rule is that the agent that wrote the code does not review it. Two reviewers ran, neither of
which wrote the code under review:

1. The built-in `/security-review` skill, run over the whole codebase rather than only the diff.
   Its discovery pass ran in a fresh sub-agent.
2. A fresh general-purpose reviewer agent, given the prompt in
   `.claude/commands/security-review-release.md` word for word. It read the code and ran the
   server to confirm what it could.

Their findings were merged with the open items in the threat model (`docs/security/threat-model.md`,
#347, PR #388; the ids in the last column are its rows) and de-duplicated. Each one was then checked by reading the cited lines on `8b600b3` before
it was filed.

## Reported, and not a finding

- **The agent's plan can be approved by the person who asked.** This is the designed flow
  ("Approved by the person who asked"). Approval needs `agent.approve`, the fingerprint must
  match, and each tool re-checks its own permission when it runs. Out of scope for a security
  issue, because changing it would change what the product does.
- **A posted debit note's supplier credit-note number and date can be set later**
  (`packages/returns/src/service.ts:377-401`). This is by design: it is audited with the old
  values, and the database trigger allows only those two columns to change.

## Checked and clean

- **Tenancy.** The company comes from the session everywhere the API reads it.
- **SQL.** Every query is parameterised.
- **`apps/web/app.js`.** No `innerHTML` built from data. The one use draws the server's own SVG
  library. Every print template escapes its strings.
- **The server issues no HTTP redirects and fetches no user-supplied URL.** (The bank-consent
  return address handed to the provider is #402.) The PDF renderer blocks all
  network access except `data:` URLs.
- **Cookies.** None are set.
- **LLMs.** No LLM call exists. The assistant and agent match a fixed vocabulary. Every agent write
  needs a preview, an approval and a matching fingerprint. The voice assistant and purchase intake
  have no API route.
